# CapsWriter 2.6.4：识别状态实时可见，界面布局与更新更稳

【新增】
· 识别等待状态实时可见：主界面录音按钮与浮窗（紧凑/展开）在"等待识别结果"时亮起状态灯并带呼吸动画，录音按钮同时显示旋转指示；状态灯由客户端真实识别任务驱动——提交、完成、发送失败、取消、断开连接、后端退出都会如实反映到界面，不再出现"录音已停但界面仍在转圈"
· 多段识别各自独立：一次讲话可能产生多个识别任务，界面会等待当前全部在途任务结束；单个片段返回结果只结束它自己的任务，不会让界面提前亮"完成"，也不再让后续片段的等待状态被前一段清掉
· 主界面改为"语音输入 / 设置"两个选项卡：服务器配置、软件更新、浮窗设置、识别与快捷键设置统一收进"设置"页，并分成"软件更新 / 浮窗设置 / 识别与快捷键设置"三组，默认收起，需要时再展开；"语音输入"页只保留录音、识别状态与最常用的快捷键开关
· 运行日志常驻显示：日志区始终展开（不再折叠在"更多"里），高度固定、内容超出时可滚动，信息更多也不用撑破窗口

【改进】
· 启动时历史日志不再影响当前状态：客户端启动或接入已在运行的客户端时，只回放此前的日志供查看，不会把历史里的"开始录音"当成当前真在录音；当前是否在录音、是否已连接、录音已持续多久，以客户端实时的只读状态回执为准，未拿到回执前界面不会给出误导性状态，也不会在空闲时错误清掉正在进行识别的任务
· 停止录音按真实结果反馈：点"停止"后界面只确认客户端真正回执"已停止"，未录音时点"停止"可立即恢复界面，不会伪造成功提示，也不会用超时装成成功
· 关机/重启前的退出握手更稳：客户端在准备退出时会先落下关闭闩锁、结束全部录音、恢复输出静音，全部完成后才回执确认；确认不到位时桌面端不会强行结束进程，可继续安全重试
· 文件替换式更新保留原文件属性与权限，逐文件备份留档，更新过程中任一步失败都能整体回滚到更新前状态；更新只写约定清单内的程序文件，用户配置、界面偏好、快捷键、日志、资源文件与桌面快捷方式一律不动

【说明】
· 本次为 2.6.4 就地功能升级；录音、快捷键、静音、保存、连接等既有行为保持不变
· 安装包与便携包由同一条 GitHub Actions 流水线从干净源码构建，附 SHA256 校验值、机器更新清单与本公告
