# CapsWriter Desktop (Windows)

Run `desktop/build.ps1` in Windows PowerShell, then place `CapsWriterDesktop.exe` beside a CapsWriter v2.6 `start_client.exe` and the modified `core/` source tree. Double click the desktop EXE. The GUI owns the tray icon and optional floating recorder; the original Python client runs hidden in the background.

The GUI saves the server address, port, recognition-context words, two independently enabled keyboard shortcuts, input mode and pause threshold in config_client.py, with a backup. The default hold shortcut is Caps Lock; the default press-once/press-again shortcut is Ctrl+Alt+Space. Click a shortcut field and press a key or chord to capture it; Esc cancels. Capturing temporarily pauses the client's global hotkeys, with automatic expiry if the UI exits unexpectedly. Settings and mode changes restart its owned backend. Closing the main window hides it to the tray; tray Exit stops the backend.

In "边说边写" mode, the client keeps recording and sends each voiced phrase when speech pauses for the configured interval (default 0.75 seconds). It omits the long silent gap and does not overlap adjacent phrases; each recognized phrase is inserted once in the current application. A 45-second safety cap prevents unlimited buffering during uninterrupted speech. This is phrase-level recognition, so words appear after a pause and server processing time, not character by character. The energy detector is intentionally small and may need a different threshold for unusually noisy microphones. In "录完再写" mode, the client records until the user releases the key or stops recording and then inserts the final text once. Switching modes is blocked during an active recording.

Recognition-context words (for example 浮窗, names, or technical terms) are sent to the server with each audio segment as a hint. They are not a forced replacement dictionary. They may improve ambiguous terms but cannot guarantee accuracy. The server remains the upstream CapsWriter server; no server code change is required for partial results. Each client configures its own server address.

The server card supports two modes. In "局域网" mode the client connects with the legacy plaintext `ws://host:port`, which is only appropriate on a trusted LAN. In "远程 wss" mode the client connects to a complete `wss://` URL (the deployment panel's gateway in front of the ASR server) and authenticates with the deployment panel's existing API key, sent as an `X-API-Key` header and validated by the panel's machine gate before the handshake is forwarded. This is the only credential the client asks for; CapsWriter does not issue its own tokens. The key is stored encrypted with Windows DPAPI under the current user (`%LOCALAPPDATA%\CapsWriterOffline\credentials.json`); it never appears in `config_client.py`, in logs, or inside a copied portable package, so moving the package to another computer requires re-entering the key. Legacy `cw.` client tokens from previous versions are detected, ignored (never silently sent as a key) and flagged in the UI with a prompt to re-enter the panel key; saving a new key clears the stored legacy value. "测试连接" saves the current settings, restarts the backend and reports the result (including an HTTP 401 hint when the key is wrong or not authorized for the voice site). Legacy `addr`/`port` settings keep working when the remote URL is empty.

The main window has light and dark themes. Its settings and log rows open when clicked anywhere across the row. The floating recorder follows the selected theme and can be dragged by its empty area. The background-density slider adjusts the opacity of the rounded floating window. The floating window uses a transparent WPF window and draws its fill inside a rounded border; system acrylic blur is disabled because its rectangular backdrop remained visible outside the rounded fill. UI preferences are saved in desktop_ui.ini beside the EXE. The application icon is drawn by desktop/generate_icon.py from simple vector shapes and built into the EXE; packaging also copies icon.ico and icon.png into assets/.

The floating recorder has four states with the existing theme colors and background density: a single microphone icon while idle (56 × 56 logical pixels); a 220 × 56 capsule while listening, with cancel on the left, a live waveform in the middle and a confirmation check on the right; a centered animated waveform while recognition tasks are pending; and a centered completion check once valid text has returned and all pending tasks finish. Clicking the idle or completion icon starts recording. The old expand/collapse and close controls are replaced by these state controls; the tray and Settings still show or hide the recorder.

The live waveform reads microphone RMS through the existing read-only UDP `LEVEL` command. No additional microphone stream is opened. The recognition animation runs independently of microphone input. The left cancel button sends `CANCEL`, which cancels active recording tasks and restores output mute through the existing recording lifecycle. Already submitted phrases may still finish and remain in the main window; cancelled sessions, empty recordings and failed sends do not produce a false completion check. The main recognition text box and its full-text copy button are unchanged.

A standalone Ctrl/Alt/Shift shortcut remains available for normal key combinations: a hold shortcut starts after its threshold only if the modifier was not used with another key, and a toggle shortcut fires on release only when tapped alone. The second tap ends recording and submits the audio for recognition. Assigning the exact same enabled shortcut to both modes is rejected. Existing mouse X2 binding in config_client.py is preserved. The GUI button uses its own recording task, so it still works if keyboard bindings are disabled.

## Software updates (软件更新)

The recognition result has a “复制” button to the right of its heading. One click copies all displayed recognition text, regardless of the current selection or automatic-copy preference. The read-only text box also supports selecting with the mouse, Ctrl+A/Ctrl+C and its context menu; long results remain available in full with scrolling. In Settings → Recognition and shortcuts, “识别完成后自动复制到剪贴板” optionally copies the completed result (all completed phrases in the current recording in phrase mode), after the backend finishes output and restores the previous clipboard. It is off by default and does not copy interim results or startup log history. In Settings → Floating window, “浮窗始终置于最顶层” immediately enables or disables always-on-top behavior (on by default). The native window z-order is reapplied on showing and during visible status refreshes, so a lost native topmost flag is repaired without activating the window or taking input focus. Both switches persist in desktop_ui.ini without restarting the backend.

Both distribution flavors check GitHub Releases for updates from inside the app: the "软件更新" card in the main window, the tray menu's "检查更新" item, or a single silent check six seconds after launch. When a newer version is found the app shows the Chinese release announcement and, on confirmation, downloads the update package for the running flavor, verifies its SHA256 from `CapsWriter-Update-Manifest.json` (once after download and once before applying), and rejects outdated versions, wrong assets, or hash mismatches.

The installed flavor waits for the app to exit and then runs the new setup silently, which upgrades in place and keeps the installation directory, configuration, hot words, UI preferences and the DPAPI-stored API key. The portable flavor hands the downloaded single-file EXE to its own launcher (`--replace-self`), which waits for the GUI to exit, transactionally replaces the original portable EXE (backup + rollback on failure), and restarts the app. Network failures never retry in a loop; the check button stays available for manual retries. The version single source is `installer/version.txt`; release builds are produced by `.github/workflows/release.yml` on GitHub Actions.
