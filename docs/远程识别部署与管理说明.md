# 远程识别与网页管理：部署与管理说明（单密钥版）

> 对应执行文档：`docs/单密钥接入改造执行文档-2026-09-29.md`；交付记录见 `docs/单密钥接入交付记录.md`
> 域名与网关（B 阶段）需在服务器现场执行；本文使用占位域名 `voice.faiz.dpdns.org` / `voice-admin.faiz.dpdns.org` 与占位 Key `sk-xxxx`，**不含真实 Key**

## 1. 接入模型（单密钥）

```
远程语音客户端 ──(X-API-Key)──→ 部署面板「网关→机器门」校验 ──→ Windows ASR :6016
浏览器管理员   ──(面板人用登录网关)──→ 同一面板入口 ──→ Windows 管理进程 :6017
局域网客户端   ──直连──→ Windows ASR :6016（是否开放由用户控制）
管理进程 ──(127.0.0.1:6019 控制通道, 本机令牌)──→ ASR 进程
```

- **只有一把 Key**：部署面板已有的 API Key。语音客户端在握手时携带 `X-API-Key` 请求头，由面板机器门校验后转发；CapsWriter 不再创建、校验、轮换任何“客户端令牌”。
- **管理页认证**：使用面板现有人用登录网关；CapsWriter 自带的密码登录保留为备用模式（`admin_auth_mode='password'`），确认网关生效后切到 `'gateway'` 模式。
- `logs/server_control.token` 是管理进程与 ASR 进程之间的本机控制通道凭据，**不是**给客户端填写的第二把 Key。

## 2. 组件与端口总览

| 组件 | 位置 | 端口 | 说明 |
| --- | --- | --- | --- |
| ASR 语音识别 | Windows（本仓库 `start_server.py`） | `0.0.0.0:6016` | 语音 WebSocket；自身不再校验令牌，资源上限保留 |
| 网页管理进程 | Windows（本仓库 `python -m admin`） | `0.0.0.0:6017` | 单页管理界面 + `/api/v1/`；独立于 ASR 进程 |
| ASR 控制通道 | ASR 进程内 | `127.0.0.1:6019` | 仅回环；管理进程专用（状态/优雅退出/日志级别） |
| 面板网关/机器门 | 部署面板（WSL Caddy） | — | 语音站点校验 `X-API-Key`；管理站点人用登录 |

## 3. 服务端安装与更新

```powershell
# 在仓库根目录（识别服务所在机器）
git pull                      # 或解压新版；管理进程零新增第三方依赖

# 启动识别服务（原有方式不变）
python start_server.py

# 启动管理进程
python -m admin --host 0.0.0.0 --port 6017                 # 自带密码登录（默认）
python -m admin --host 0.0.0.0 --port 6017 --auth-mode gateway   # 面板网关保护生效后切换
```

认证模式也可写入 `admin_settings.json`（`{"admin_auth_mode": "gateway"}`）持久化。

- **password 模式**：首次启动自动生成管理员密码，只在控制台显示一次；修改密码 `python -m admin set-password`。
- **gateway 模式**：不再有密码表单；每个请求须携带面板网关注入的用户请求头（默认探测 `X-Remote-User`/`X-Forwarded-User`/`X-Auth-Request-User`/`Remote-User`，可用 `gateway_user_headers` 按面板实际注入的头名调整）。**前提**：管理域名整站受网关保护，且 Windows 防火墙把 6017 来源限制为网关，防止伪造头直连。切换前必须先验证：直连 6017 的未带头请求被拒绝、经网关登录的请求可正常操作。

开机自启（二选一，不要同时启动两个模型实例）：

- 计划任务（推荐）：开机延迟 1 分钟执行 `python -m admin`。管理进程默认不自动拉起 ASR；在网页上点击「启动」即可，避免开机风暴。
- 延续原有方式：保留现有 `start_server.py` 开机任务，管理进程通过 PID 文件/互斥锁识别已运行的 ASR（绝不拉起第二个实例）。

## 4. 网页管理

浏览器经管理域名（或局域网 `http://<服务器IP>:6017/`）打开。

- **状态行**：在线/启动中/识别中/异常/已停止、模型、连接数、运行时长、内存、显存（不可用时明确标注）。
- **安全重启**：先显示活跃连接数并等待会话空闲（上限 120 秒），再优雅退出、重新拉起；「停止」需二次确认；不会产生第二个 ASR 实例。
- **热词**：编辑 `hot-server.txt`，带冲突检测（他人先改过则 409）；保存后需重启识别进程生效（服务端在模型加载时读取热词）。
- **设置**：白名单字段（模型选择、日志级别、对齐引擎空闲释放、GPU 预加速开关）；写入 `server_settings.json`（原子替换 + `.bak` 备份），改模型需重启。
- **日志**：5 秒增量轮询、可暂停；`X-API-Key`、`Bearer`、旧令牌、控制通道令牌等敏感字段自动脱敏；页面切到后台自动停发请求。
- **审计**：登录/网关访问、设置修改、进程控制均有记录（`admin/data/audit.log`）。
- 页面**没有**任何客户端密钥管理；写操作仍有 CSRF/Origin 校验与二次确认。

## 5. 客户端配置（唯一 Key 输入项）

1. 桌面客户端「服务器」卡片 → 选「远程 wss」→ 填完整地址（如 `wss://voice.faiz.dpdns.org`）→ 粘贴**部署面板 API Key** → 保存/测试连接。
2. Key 以当前 Windows 用户 DPAPI 加密存于 `%LOCALAPPDATA%\CapsWriterOffline\credentials.json`，不进配置文件、不进日志、不进便携包；便携包复制到新电脑需重新录入。
3. 客户端握手发送 `X-API-Key: <面板Key>`；网关校验通过后转发到 ASR。
4. **旧版升级**：上一版本使用的 `cw.` 开头客户端令牌会被自动忽略，界面提示“重新录入部署面板 API Key”，不会被静默当作 Key 发送；录入新 Key 后旧值自动清除。
5. 局域网 `ws://` 模式继续可不填 Key（若已在凭据存储录入 Key，直连时也会带上该头，对直连无影响）。

## 6. 公网发布（B 阶段现场执行清单）

按顺序执行，任一步失败先回滚该步：

1. **备份**：`config_server.py`、`hot-server.txt`、防火墙规则、面板路由、当前 `start_server.py` 启动方式、旧版源码提交号与便携包。
2. **面板登记语音流水线**：语音域名 → Windows ASR `6016`，确认代理支持 WebSocket Upgrade 与长连接；不手改 Caddyfile。
3. **语音站点启用「网关 → 机器门」**：覆盖语音 WebSocket 实际路径（根路径服务用整站模式 `/*`，以实际请求验证匹配）；给现有面板 Key 增加该站 `gate.pid` 权限，保持原 Key 不变。
4. **管理站点配置人用登录网关** → Windows `6017`。先验证未登录用户无法访问页面与管理 API。
5. **网关验证通过后**，管理进程切 `--auth-mode gateway`（或写 `admin_settings.json`），并配置 Windows 防火墙：6017 只放行网关来源；`6016` 既有 LAN 规则按用户决定处理，不映射 6016/6017 到路由器公网。
6. **验收门禁**（全部通过才切正式域名）：
   - 不带 `X-API-Key` / 带错误 Key 连语音域名 → 网关拒绝，ASR 不收到连接；
   - 带现有 Key → WebSocket 升级成功并完成一次真实识别；
   - 长按、按键开关、边说边写、录完再写各测一次；断线重连不重复输入；
   - 未过网关登录时读不到状态/日志、执行不了启动/停止/重启；
   - 日志、便携包、仓库中搜不到真实 Key。

## 7. 故障排查速查

| 现象 | 排查顺序 |
| --- | --- |
| 客户端提示 HTTP 401/403 | 面板 Key 错误、未授权语音站点、或机器门路径未覆盖 → 面板检查 Key 的站点授权与网关路径配置 |
| 客户端提示“检测到旧版客户端令牌” | 上一版 `cw.` 令牌残留 → 重新录入面板 API Key（旧值会被忽略与清除） |
| 管理页显示“请先通过面板登录” | gateway 模式下未过网关或网关未注入用户头 → 检查面板网关配置与 `gateway_user_headers` 头名 |
| 管理页打不开（502） | 管理进程未运行 → RDP/SSH 后 `python -m admin`；检查面板路由 |
| Cloudflare 1033 | Tunnel 离线 → 服务器上检查 cloudflared 与 WSL |
| 网页显示「异常/无响应」 | ASR 进程在但控制通道不通（如 6019 被占）→ 重启识别服务；PID 核对失败时页面会明示 |
| 网页显示「已停止」但端口被占 | 其他进程占用 6016 → 管理进程拒绝启动新实例以免双实例，先处理占用 |
| 模型加载失败 | 看日志卡片具体原因（模型缺失/显存不足/端口占用/权限），处理后在网页点「启动」 |
| Key 疑似泄漏 | 在部署面板吊销/轮换该 Key 并更新客户端；CapsWriter 侧无密钥存储需要清理（DPAPI 文件重新录入即可） |

## 8. 安全边界备忘

- **语音接入**：`X-API-Key` 由面板机器门在转发前校验，ASR 不接触 Key；ASR 保留连接数上限（8）、单消息上限（64MB）、帧队列上限，超限握手直接拒绝，不拖垮模型进程。
- **Key 的存放**：客户端仅在 DPAPI 凭据存储；日志输出统一脱敏（`X-API-Key:`、`Bearer`、`cw.*`、`ctrl.*`）；仓库与便携包中不得出现真实 Key。
- **管理页**：password 模式下密码 PBKDF2 存储、会话 HttpOnly+SameSite=Strict、登录限速；gateway 模式依赖网关用户头 + 防火墙来源限制。两模式写操作均要求 CSRF double-submit + Origin 同源。
- **控制通道**：仅回环 + 独立令牌（`logs/server_control.token`），命令白名单（status/shutdown/set_log_level），不接受任意命令。
- **进程核对**：PID 文件含进程创建时间，杜绝 PID 复用误杀；单实例互斥锁 `Local\CapsWriterOfflineASR`。
- **回滚**：旧版（`f969deb` 及之前）从 git 恢复即可重新启用 `server_tokens.json` 令牌体系；磁盘上的 `server_tokens.json` 不会被本次改造自动删除。
