## 1. 必修问题：按依赖顺序一次改完

### P0-01：流水线列表解析和域名核对会失效

`deploy/voice-setup.sh` 的 `create_pipe()` 把 `GET /api/pipelines` 响应当字典调用 `.get(pid)`；现网返回数组。错误被 `2>/dev/null || true` 吞掉，两个域名变空，脚本只警告并继续。改为数组按 `id` 精确匹配，检查 `domain`/`domains` 确实分别是 `voice.<BASE_DOMAIN>`、`voice-admin.<BASE_DOMAIN>`；API 失败、找不到、重复 ID、绑定错误、流水线处于停用状态均非零退出。不要用临时文本文件和空字符串继续。已有同 ID 流水线若配置不属于本方案，拒绝覆盖。

### P0-02：机器门调用必然触发未绑定变量

同脚本 `GATE_BODY=$(ASR_PID=... PATHS=... python3 ... "$ASR_PID" ... "$PATHS")` 在 `set -u` 下展开未定义的 Shell 变量。把 `ASR_PID` 作为 Shell 变量先赋值，位置参数直接传 `"$ASR_PID" "$ADMIN_DOMAIN" "$GATE_PATHS"`；删去多余内联环境赋值。运行完整 Bash 测试必须走到 `gate-body`。

### P0-03：安全门必须先于任何可服务的代理，并确认**运行态**生效

当前顺序是建站 → 上传/部署两个代理 → `POST /api/gate`。部署完成至设门之间，语音域名可能无 Key 可达；P0-02 使流程在设门前退出。建议创建/更新 ASR 流水线时就在 `pipeline_body()` 里带 `apikey_gate: {enabled: true, paths: ["/*"]}`，使首次路由生成即带机器门；管理域名加入人用网关后，**先验证两个门的运行态，再上传/部署代理**。旧的同 ID 代理若已运行，重新保存时也不得出现无门间隙。机器门失败、Caddy 重载失败、配置读回不一致时停止，不部署。对无 Key/错误 Key 的真实 WS 握手做拒绝测试；普通 GET 的 401/426 只作辅助信号。

### P0-04：HTTP 成功不代表面板配置生效

`POST /api/pipelines` 可能返回 `warnings`；`POST /api/gate` 的 `update_gate()` 先保存配置，再调用 `apply_gate()`，Caddy/Authelia 错误作为 `warnings` 返回；`deploy_service.py` 在 Caddy 重载失败后仍写成功标记。脚本目前只看 `curl -f` 和部署日志标记。逐步解析 `ok`、`id`、`warnings`，警告视为阻断；部署后核查容器、面板当前版本、Caddy 路由与鉴权实测。若保存态与运行态分叉，明确报错并阻止后续步骤，不宣称部署完成。

### P0-05：管理站点人用网关可能实际未启用

`voice_setup_lib.gate_body()` 只追加 `domains`，沿用原网关的 `enabled`。若原值为 false、该域名在 `exempt` 列表中、Authelia 策略未应用，管理页可能直通。脚本在更新前检查 `GET /api/gate` 的 `enabled`、原域名与免过门配置；不满足前置条件就停止并清楚报告，避免擅自重写用户其他站点。更新后读回并实测未登录的页面和 `/api/v1/status` 都被挡；已登录请求能收到可信用户头。管理进程切 `gateway` 模式只能在这些检查成功后进行。

### P0-06：服务器现有 ASR 仍是旧打包版，源码改动未上线

仓库 A 阶段删除了 ASR 自建客户端令牌并新增 `127.0.0.1:6019` 控制通道，但服务器目前运行的是旧 `start_server.exe`；复制新 `.py` 文件到其旁边不能证明 PyInstaller EXE 改了内嵌代码。实际目录未见本版 PID/控制令牌文件。先以**可回滚的新服务端产物**更新 ASR，再核对版本/代码行为、单实例、模型目录、WS 握手与控制通道；保留旧 EXE、模型与配置备份。现有 90 秒延迟开机脚本要指向新产物或在切换后停用，避免重启时又拉起旧版或双实例。切换过程不要重启 Windows 主机。

### P0-07：管理进程不能直接控制现有打包服务

`admin/config_admin.py` 默认 `repo_dir=源码仓库`、`asr_entry=repo_dir/start_server.py`，PID、控制令牌、日志、热词、设置路径也都指向该目录；`admin/asr_control.py::_start_process` 固定运行 `[sys.executable, str(entry)]`。服务器 ASR 实际是另一个目录里的 `start_server.exe`，且 Windows 没有已确认可用的独立 Python 环境。只“安装 Python”仍不能让启动按钮管理打包版。为管理端建立**明确的服务器目录/启动命令配置**：可启动 EXE 或 Python 脚本；所有状态/热词/设置/日志/控制令牌都指向同一实际 ASR 工作目录。若管理端本身打包，包含 `websockets` 依赖并验证启动、停止、重启、模型切换、热词和日志；若走 Python，先验证版本/依赖/工作目录。对旧版无控制通道的情况明确显示不可控，不要误报“已停止”并启动第二个模型。

### P0-08：管理端直连可伪造网关用户头

`admin/webapp.py::_require_gateway` 只检查 `X-Remote-User` 等头有值；直连 6017 的请求若可达，可自填头，再从 `/api/v1/bootstrap` 取得 CSRF cookie 并调用管理 API。这是当前设计所依赖的网络边界，不是第二把 API Key。上线时必须验证 Windows 防火墙的 6017 只允许**实际网关来源**，其他 LAN 机器直连携带伪造头也不能进入；同时核对 Caddy/Authelia 覆盖或清除客户端自带的同名头。没有这组实测，不切 `gateway` 模式。

### P1-09：已验证的面板 Key 仍会流到 ASR 上游

`deploy/voice-gateway/Caddyfile.template` 仅写 `reverse_proxy __UPSTREAM__`，无移除 `X-API-Key` 的规则；面板 Caddy 的 `forward_auth` 负责验证，并不自动清掉原请求头。网关容器应在转发 Windows ASR 前移除 `X-API-Key`，以及机器门复制的仅内部使用请求头；用假 Key 的测试上游确认收不到。文档“ASR 不接触 Key”在修复/验证前不成立。保留面板机器门所需头，**只能在认证通过后的内层代理移除**。

### P1-10：脚本最后验证不决定退出码

无 Key/带 Key 的 `curl` 返回 `000`、`200`、`403`、`502` 等时，当前脚本仍打印“剩余人工步骤”并退出 0。把验证结果分成明确状态：门未生效/链路断/站点授权待办/网关通但需真录音；只有全部自动可验项目达标才返回 0。站点授权确实需在面板 UI 给**同一把现有 Key**勾选 `voice-asr-prod`，不得新建 CapsWriter Key；授权前以“待人工步骤”非零或独立状态退出，不报部署成功。真实 WebSocket/识别和管理页认证仍列为现场验收。

### P1-11：脚本运行鲁棒性与重复执行

当前把 `.voice-setup-domains.tmp`、`.voice-setup-gate.json` 写在脚本目录，复跑/并发执行会互相覆盖；部分失败分支留文件。改为安全临时目录加 `trap` 清理和单实例锁，或完全用 Shell/Python 变量传递。所有 `curl` 调用加连接/总超时；日志轮询读取失败不能被当作“仍在部署”无限误导，超时应查询任务/容器最终状态并报告。`deploy_verdict` 应以末次终态为准，不能只因日志任意位置有旧成功词就压过后续失败。所有错误摘要遮挡可能出现的 Key。

### P1-12：便携包和操作文档尚未与源码一致

`CapsWriterDesktop.exe` 的构建时间早于单密钥 UI 源码；当前没有已交付的新客户端便携包，也没有新版服务端/管理端产物路径与 SHA-256。按目标发行形态重新编译、打包、在产物中检查 `credentials.py`、`websocket_manager.py`、`config_client.py` 与桌面 EXE 均为同版；在干净 Windows 用户下做一次双击启动/录音/重连。原部署说明里“LAN `ws://` 会发送已保存 Key”“ASR 不接触 Key”“管理进程零新增依赖”三处与现代码或当前网关不符，本轮已把这些文字改为真实状态；ZCode 修复代码后须再次核对说明，并更新交付记录与网关 README。

### P1-13：仍允许把面板 Key 留在明文客户端配置

`core/client/connection/websocket_manager.py::_config_api_key()` 优先读取 `config_client.py` 的 `ClientConfig.api_key`，再读 DPAPI；`desktop/README.md` 却断言 Key 永不进入配置文件。GUI 当前不会写入，但手动配置或旧包覆盖后可能把明文 Key 打进便携包，并覆盖新录入的 DPAPI Key。统一只从凭据存储读取；若检测到配置文件中的非空 Key，提示迁移并清掉配置值，不回显、不自动打包。测试明文配置不会优先于 DPAPI，也不会混入产物。

### P1-14：远程模式仍可保存明文 `ws://`

`desktop/CapsWriterDesktop.cs::SaveSettings` 对“远程”地址接受 `ws://` 与 `wss://`，而 Python 客户端对 `ws://` 不发送 Key，仅打印警告后仍尝试连接。UI 应在远程模式拒绝 `ws://`，明确提示改 `wss://`；局域网模式保留现有 `ws://`。同时检验 URL 的凭据、查询参数不能意外包含或记录 Key，并用一个 UI/配置级测试覆盖模式切换。
