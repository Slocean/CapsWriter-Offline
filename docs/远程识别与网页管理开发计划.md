# CapsWriter-Offline 远程识别与网页管理开发计划

> 交接对象：在现有 fork `https://github.com/Slocean/CapsWriter-Offline` 上开发的智能体
> 基线：`codex/unified-client-live-preview` / `master`，计划编写时提交 `a9fdd48`
> 计划日期：2026-09-29
> 性质：实施规格与验收清单；本文档本身不表示公网已开放

## 1. 目标和明确边界

在**同一个 fork 仓库**中完成三件事：

1. 现有 Windows 客户端保留 `ws://192.168.0.104:6016` 局域网连接，同时支持带独立客户端凭据的 `wss://` 公网域名。
2. Windows 服务器上的语音识别进程继续使用现有模型和 WebSocket 协议；新增独立、轻量的管理进程及单页网页，取代日常查看终端、改配置和手工重启的流程。
3. 复用服务器现有的 Cloudflare Tunnel、WSL、部署面板和 Caddy 入口，通过域名发布**已经完成鉴权**的语音接口及管理网页。

交付后的日常操作应是：服务器开机后进程自动恢复；用户在浏览器查看状态、日志、热词和配置并安全重启；桌面客户端可在局域网地址与远程域名之间切换。**网页管理端不承担浏览器麦克风录音或向任意电脑的当前输入框注入文字**，这仍由桌面客户端完成。语音接口不能先公开再补鉴权。

不新建独立 Git 项目；允许同仓库内有 Windows 识别进程、Windows 管理进程和 WSL 反代容器三个运行单元。网页保持一个主页，暗/亮主题，避免多级菜单式管理系统。优先少依赖、少常驻资源、清楚显示错误和恢复方式。

## 2. 已核对的现状与实施前复核

### 2.1 仓库现状

- `start_server.py` → `core/server/app.py` 启动识别子进程、托盘和 `core/server/connection/server_manager.py` 中的 WebSocket 服务。当前服务端配置在 `config_server.py`，默认监听 `0.0.0.0:6016`。
- `core/server/connection/ws_recv.py` 接受连接后立即登记客户端并处理 JSON/音频消息；目前没有握手鉴权。`websockets.serve` 使用 `max_size=None`，面向公网前必须评估消息大小、连接数和内存上限。
- `core/client/connection/websocket_manager.py` 只会拼 `ws://{addr}:{port}`，没有完整 URL 或凭据配置；`desktop/CapsWriterDesktop.cs` 的服务器输入框也只允许主机名/IP 与端口。
- 当前桌面客户端提供长按、按键开关、浮窗、边说边写和录完再写；这些行为及现有消息格式在改造中必须保留。
- 当前 `desktop/package.ps1` 从已有客户端目录制作便携包。新增 Python 客户端模块、配置项和 UI 代码时，需同步更新打包步骤；不能只改源码后声称便携版已更新。

### 2.2 服务器现状

- 识别服务运行在 Windows 主机 `192.168.0.104:6016`。2026-09-29 的只读检查确认 WSL 可以连到该端口；这不等于 WSL 容器、域名和新管理端口已经配置成功，均需现场测试。
- 公网入口现为 Cloudflare → Tunnel → WSL Caddy/部署面板。部署面板负责生成 Caddy 路由，**不要直接修改** `/srv/docker/caddy/Caddyfile`，否则后续部署可能覆盖。
- 服务器 Windows 曾因模型启动和防火墙弹窗卡顿。迁移进程管理时必须避免同时启动两个模型实例，避免在无人可恢复的情况下改变已有开机流程。
- 运维资料位于 `C:\Users\bigse\.codex\notes\faiz-operations-manual-summary.md`。它含历史快照；实施前复核线上隧道、面板、路由和防火墙。SSH 入口为 `ssh -p 2222 bocean@192.168.0.104`，只读检查优先。

## 3. 推荐架构

```text
局域网客户端 ───────────────────────────→ Windows ASR WebSocket :6016

外网桌面客户端 ─→ Cloudflare Tunnel ─→ 部署面板 Caddy ─→ 轻量网关 ─→ Windows ASR :6016
浏览器管理员   ─→ Cloudflare Access ─→ 同一入口/轻量网关 ─→ Windows 管理进程 :6017

Windows 管理进程 ─→ 本机受限控制通道 ─→ Windows ASR 进程及模型子进程
```

建议域名先用占位名 `voice.faiz.dpdns.org`（ASR）和 `voice-admin.faiz.dpdns.org`（管理页），最终名称在发布前按服务器域名冲突检查确定。网关是部署面板管理的极薄后端容器，只做 Host 路由、WebSocket Upgrade 转发和访问边界；不加载模型、不保存音频、不持有管理凭据。若当前部署面板经现场验证支持直接把域名代理到 Windows 上游，可省去网关容器；不要为省一个容器手改面板生成的 Caddyfile。

Windows 管理进程要与 ASR 进程分开运行：识别服务停止或崩溃时，管理页仍能显示故障并执行恢复。管理进程可用 `aiohttp` 加静态 HTML/CSS/JS；前端构建工具不是运行时依赖。建议将运行时状态、配置操作、进程控制拆成模块，不在 HTTP 路由里直接拼 shell 命令。

### 3.1 三条鉴权边界

1. **语音 WebSocket：**为每个客户端生成独立高熵令牌；客户端在握手 HTTP 头中提交，服务端在登记 socket、读取音频之前验证。服务端仅保存令牌哈希，比较使用常数时间函数，可单独吊销或轮换。无令牌、错令牌和已停用令牌均在升级前拒绝。不能把令牌放 URL、日志、源代码或截图里。局域网旧客户端的兼容策略要显式配置：默认只允许可信 LAN 地址沿用旧行为；公网路径绝不匿名。若无法可靠识别来源，则所有连接统一要求令牌，并提供迁移步骤。
2. **管理网页：**Cloudflare Access 限定管理员身份，同时管理服务本身验证 Access 身份或使用独立管理员登录/session，防止通过错误的网络路由绕过边缘认证。管理 API 的写操作要有 CSRF 防护、权限检查、审计日志；cookie 使用 Secure、HttpOnly、SameSite。不能复用客户端语音令牌作为管理员权限。
3. **管理进程到识别进程：**只走本机受限 IPC/回环控制接口；只允许明确的状态、优雅退出等命令，不接受任意命令行或文件路径。管理进程要核对可执行文件绝对路径、PID 和工作目录，防止杀错进程。

Cloudflare Tunnel 支持 WebSocket；仍需为长连接配置合理的 ping/pong 和客户端自动重连，验证空闲断开后的恢复。参考官方说明：<https://developers.cloudflare.com/cloudflare-one/faq/cloudflare-tunnels-faq/>、<https://developers.cloudflare.com/network/websockets/>、<https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/>。

### P1：安全的语音连接和客户端远程配置

**服务端任务**

- 在 `core/server/connection/server_manager.py` 的握手阶段加入令牌校验，拒绝后不得进入 `ws_recv`、不得分配音频缓存/会话。令牌管理放在独立模块，配置和哈希存储采用原子写入、最小权限、自动备份。
- 对 WebSocket 消息大小、同时连接数、每连接待处理数据量和异常重试设置明确上限。上限由现有麦克风分段和文件转录消息实测后确定；文件转录不能因默认小包上限被误伤。拒绝超限连接时返回可诊断错误，不拖垮模型进程。
- 为启动、认证失败、断线、识别错误做结构化但不含音频/令牌的日志。连接数统计使用 `ServerState.sockets`，并确保异常断开时清理。

**客户端任务**

- 在 `config_client.py` 增加可选完整 `server_url`（`ws://`/`wss://`）和客户端凭据引用；旧 `addr` + `port` 继续可用，不做静默破坏式迁移。凭据保存在当前 Windows 用户可读的独立配置/系统凭据空间，不直接写进可分发便携包。至少保证 UI 显示掩码、日志不输出值；若用 DPAPI，应说明拷贝便携包到另一台电脑需重新输入令牌。
- `core/client/connection/websocket_manager.py` 使用完整 URL、握手头、证书校验和断线重连。公网连接不得允许关闭 TLS 验证；局域网 `ws://` 需在 UI 明确标注仅适合可信网络。
- 在桌面主界面把“服务器配置”做成清晰的“局域网地址 / 远程地址”选择与连接状态；支持保存和连接测试。保留快捷键、浮窗、两种写入模式，切换地址时不丢设置。修订 `desktop/package.ps1`，确保便携包中确实含新客户端代码。

**完成条件**：老客户端本地协议回归通过；新客户端在 LAN 正常识别；通过本地代理的 WSS 测试可识别；错误/撤销令牌在握手时拒绝；日志与便携包中搜索不到令牌明文。

### P2：Windows 管理进程与可恢复的进程管理

**任务**

- 新增同仓库的 Windows 管理程序（建议 `admin/`）。它不加载 ASR 模型；负责健康检查、只读状态、受限配置修改、日志读取、令牌轮换、启动/停止/重启 ASR。单独的启动器或 Windows 计划任务保证管理员进程开机后可用。
- ASR 进程改为可被管理器可靠地识别和优雅关闭；通过独立进程、PID/路径/端口三重检查和互斥锁保证模型最多启动一个实例。若识别进程启动失败，网页管理仍存活并显示原因。对 GPU 显存不足、模型缺失、端口占用、权限错误分别给出可理解提示。
- 重启之前检查正在识别的会话数，默认等当前录音/识别完成或到达上限时间后再执行；UI 显示等待状态。强制中断须有明显的二次确认。故障恢复要有超时、退避和单次重试上限，避免启动风暴再次卡死 Windows。
- 用明确的配置文件替代网页对 `config_server.py` 的文本编辑；第一版只开放经过校验的字段（模型选择、可编辑热词、日志级别及必要的资源开关）。保存先校验、原子替换、备份；影响模型的更改提示并执行受控重启。
- 热词编辑读取/保存 `hot-server.txt`，尊重现有文件监听与编码；不让网页编辑任意路径。日志 API 限行数和字节数，默认不展示完整识别文本，绝不展示令牌、Cookie 或原始音频。

**完成条件**：浏览器中能看见“在线/启动中/识别中/失败”、模型类型、连接数、最近错误、进程内存/显存（读不到显存时明确标示不可用）；启动/停止/重启不产生双实例；管理进程在 ASR 崩溃后仍可操作；Windows 重启后可恢复。

### P3：单页网页管理端

**页面内容**

- 顶部一行：服务状态、当前模型、连接数、上次健康检查；主按钮为安全重启。
- 同页折叠区域：客户端令牌（新增、命名、禁用、轮换；只在创建时显示一次）、热词、可修改配置、最近日志与错误。不要放任意 shell 终端、文件管理器或全系统进程列表。
- 暗/亮主题、桌面与手机宽度适配、清晰的加载/失败/已保存反馈。日志轮询采用低频或 SSE，并提供暂停；页面关闭后不得持续向服务端发请求。
- 所有写操作显示影响范围；“重启”显示活跃会话数与等待进度。危险操作和网络错误不能出现按钮无反应。前端对日志和热词做 HTML 转义，设置 CSP，避免 XSS。

**接口约定（版本化，例如 `/api/v1/`）**

- `GET /health`：网关/管理进程自身存活，不要求 ASR 正常。
- `GET /api/v1/status`：ASR 生命周期、模型、连接数、版本、最近错误，**不含秘密**。
- `GET /api/v1/logs?cursor=...`：有界增量日志；服务端清洗敏感字段。
- `GET/PUT /api/v1/settings`、`GET/PUT /api/v1/hotwords`：只读/白名单写入，支持校验和冲突检测。
- `POST /api/v1/actions/{start|stop|restart}`：幂等任务 ID、当前状态和进度；不能允许任意字符串命令。
- `GET/POST/DELETE /api/v1/client-tokens`：列表只返回 ID、名称、创建/末次使用/状态；创建响应仅一次返回明文。

明确 HTTP 状态：401 未登录，403 无权限，409 状态冲突，422 配置错误，429 操作过频，5xx 附请求 ID。页面不得根据 HTTP 200 猜测操作成功，必须读取结果状态。

**完成条件**：不看终端即可完成日常查看与安全重启；未授权访问管理页/API 均失败；同一页面完成主要操作，无多级菜单依赖。

### P4：域名、网关和上线

**任务**

- 通过部署面板创建受管理的后端流水线，优先沿用已有根域与通配 Tunnel DNS。轻量网关容器仅把 ASR 域名的 WebSocket 请求转到 Windows `6016`，把管理域名请求转到 Windows 管理进程；外层 Tunnel/Caddy 保持由面板管理。验证 Host、Upgrade、超时、请求体上限和真实源 IP 传递。若一个流水线绑定两域名不可用，拆成两个同源网关流水线。
- 管理域名先配置 Cloudflare Access allow policy，确认非授权用户被挡住，再让域名路由上线；源站仍必须校验管理员身份。语音域名不使用交互式登录页，依赖每客户端令牌并限制连接资源。路由配置只开放所需 host/path，不将 Windows 的 `6016` 或 `6017` 映射到家庭路由器公网端口。
- Windows 防火墙只允许必要的 WSL/网关到新管理端口；WSL NAT 来源可能改变，必须跨 Windows/WSL 重启复测。现有 LAN `6016` 规则不可被无意覆盖。按当前部署面板规范更新外部服务登记和运维说明。
- 先用测试域名/测试客户端验证，再迁移一台便携客户端；保留局域网配置作为回退。只有公网匿名拒绝、Access 阻断和 WSS 正常识别都通过，才切换正式域名。

**完成条件**：外网客户端经 `wss://` 完成一次长按识别和一次按键开关识别；管理员通过浏览器登录并查看状态；未授权请求无法连接音频或读写管理 API；原局域网客户端仍可用。

## 5. 测试矩阵和发布门禁

1. **协议回归**：旧 LAN 客户端、长按 Caps Lock、开关 Ctrl+Alt+Space、浮窗按钮、边说边写、录完再写、文件转录分别测试；一次结束不能删掉已输入全文再重输。
2. **认证**：缺/错/撤销令牌握手拒绝；有效客户端只可访问 ASR；非管理员无法打开页、读日志、改热词或重启；CSRF、XSS、过期会话、错误 Origin 和直接访问 Windows 管理端口测试。
3. **网络**：局域网、外网 WSS、断网重连、Cloudflare 空闲断线后重连、大音频分段、代理 Upgrade；不因网络抖动产生重复文本或无限积压。
4. **资源**：空闲常驻内存和 CPU 对比基线；单个恶意大帧、多连接和短时重连不能耗尽服务器；模型仍只加载一份。记录测试环境与实测值，不先写臆测数字。
5. **故障**：模型缺失、GPU 不足、6016 被占、管理进程重启、ASR 崩溃、Windows 重启、WSL/隧道重启、Tunnel 502/1033。网页给出可操作提示，旧 LAN 通道可回退。
6. **发布前安全门禁**：正式域名未授权响应、令牌泄漏搜索、日志脱敏、部署包与 SHA-256、Access policy、Windows 防火墙范围、回滚脚本演练全部有记录。任一门禁失败，不发布语音公网路由。

自动化测试覆盖 URL 兼容迁移、令牌校验、配置原子写入、进程状态机和 API 权限；跨 Windows、GPU、Tunnel 的部分做真机集成测试。测试通过后再改生产启动方式，避免先影响正在使用的服务。

## 6. 回滚和故障恢复

- 每个里程碑可独立提交；P1 先以新配置开关关闭，P2 管理进程先只读上线，P4 最后开放公网。不要一次替换所有层。
- 保留旧版服务端二进制/源码、`config_server.py`、热词、启动任务和防火墙规则的备份。管理页失效时直接用原有 LAN/SSH 检查；反代失效时先撤销域名路由，不停止局域网 ASR。
- 若新服务端异常，先停止新管理器的自动拉起，再确保只剩一个 ASR 进程，恢复旧启动方式及配置，验证 `192.168.0.104:6016` 可识别。切勿在服务繁忙时强杀模型进程或执行会触发 Windows 防火墙弹窗的启动方式。
- 令牌疑似泄漏时先撤销该客户端令牌，重新签发并更新对应客户端；不要为了恢复可用性把公网认证关掉。

## 7. 给实施智能体的执行要求

1. 先读本计划、仓库实际代码以及服务器运维摘要；对本文“2026-09-29 已核对”的事实重新现场核验。不要把历史快照当作现行指令。
2. 保留同一 fork、现有协议、当前 LAN 服务和客户端交互；新配置必须兼容旧配置。不要新建另一个不相关项目，也不要修改 `VoiceType` 仓库。
3. 第一阶段只在本地和测试域名工作；完成认证、测试、回滚后才开放公网。生产变更先备份、再逐层部署、每层验证。面板生成的 Caddyfile 不手改。
4. 不将私钥、Cloudflare Token、客户端/管理员明文令牌、语音原文或真实用户凭据提交 Git。日志和错误信息也须脱敏。
5. 每阶段交付可复核证据：提交 ID、测试命令/结果、包校验、服务状态、域名/鉴权测试、回滚入口；遇到阻塞只报告具体证据，不以“应该能用”代替验证。

## 8. 待实施时确认的少量决策

- 最终两个域名的名称及 Cloudflare Access 允许的管理员身份；默认候选为 `voice.faiz.dpdns.org` 与 `voice-admin.faiz.dpdns.org`。
- 是否允许旧 LAN 客户端免令牌；安全优先的默认建议是迁移完成后所有客户端统一鉴权。
- 文件转录是否允许走公网；默认先只开放麦克风识别，确认帧大小和资源限制后再开放文件转录。
- 客户端令牌保存方式：优先当前 Windows 用户 DPAPI；跨机器便携时由用户在新机器重新录入。

这些决策不妨碍 P0 的现场核对、P1 的可配置实现和 P2/P3 的本地开发；不要因为尚未确定域名名称就停下全部工作。
