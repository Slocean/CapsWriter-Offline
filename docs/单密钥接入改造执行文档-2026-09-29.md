## 1. 已确定的产品决定

用户自己管理服务器和对外入口。远程语音客户端只配置**部署面板已有的一把 API Key**；CapsWriter 不再创建、校验、轮换或要求第二把“客户端令牌”。不得为了此功能新建独立仓库或再设计一套用户需要维护的密钥系统。

语音入口由部署面板的「网关 → 机器门」校验请求头 `X-API-Key`，通过后再转发 WebSocket 握手和音频流。局域网直连是否开放由用户控制。网页管理端使用部署面板现有的人用登录网关，不再要求 CapsWriter 自己的管理员密码。浏览器直接打开网页不会自动携带 `X-API-Key`，所以不要把“机器门”当作管理网页的登录页。

ASR 进程与网页管理进程之间、仅供本机使用的 `logs/server_control.token` 是内部控制通道凭据，不是客户端要填写的第二把 API Key；这次保留它，避免误删进程管理机制。

## 2. 2026-09-29 现场核对结果

- 服务器部署面板的**运行容器**已有 `panel/services/apikey_authz.py`。当前面板源码的站点机器门会由 Caddy `forward_auth` 向 `/internal/authz/apikey` 查询，按站点和路径校验面板 API Key，响应 200/401/403。机器门的路径在「网关」配置；现有 Key 可在「API 密钥」页面增加该站的 `gate.pid` 权限，无需生成第二把 Key。
- 面板文档 `docs/12-认证网关.md` §2.2 和 `docs/13-API密钥与开放接口.md` §6b 明确描述了这一能力。此前 ONELEDGER 的 2026-09-27 运维摘要没有覆盖这项细节；实施时以当前运行代码和面板界面为准。
- 只读列出 `/srv/apps/pipelines.json` 的流水线 ID，未发现名称包含 `voice` 或 `caps` 的流水线；不能据此断言所有其他命名的语音流水线都不存在，实施前仍需在面板中核对。
- CapsWriter 当前仍有独立令牌：客户端用 `Authorization: Bearer`，ASR 用 `TokenStore` 验证，管理页有“客户端令牌”增删/轮换入口，默认 `auth_mode='lan_legacy'`。这些与单密钥目标冲突。
- 本次只读核对，没有修改服务器、面板配置、CapsWriter 源码，也没有重启任何服务。

## 3. 实施顺序

### A. 先修改 fork，保持可回滚

1. 在 `core/client/connection/websocket_manager.py` 中，远程 `wss://` 模式使用 `X-API-Key: <部署面板 Key>` 发起 WebSocket 握手，不再发送 CapsWriter 的 `Authorization: Bearer`。局域网 `ws://` 模式继续可不填 Key；保留重连、证书校验和原有语音消息协议。
2. 在 `desktop/CapsWriterDesktop.cs`、`core/client/connection/credentials.py` 和 `config_client.py` 中，把“客户端令牌”改为“部署面板 API Key”。继续遮挡输入并用当前 Windows 用户的 DPAPI 保存。旧的 `cw.` 令牌不能被静默当作面板 Key 发送；检测到旧值时提示重新录入。不得把 Key 放进便携包、普通配置文件、URL 查询串或日志。
3. 在 `core/server/connection/handshake.py`、`server_manager.py`、`auth.py` 和 `config_server.py` 中移除对外客户端的 `TokenStore`、`auth_mode` 与令牌校验。**保留** WebSocket 握手阶段的连接数上限、消息体积限制、并发和异常清理。不要因为删认证而退回 `max_size=None` 或放宽资源限制。
4. 在 `admin/webapp.py`、`admin/settings_store.py`、`admin/static/index.html`、`admin/static/app.js` 中移除“客户端令牌”接口/UI 和“鉴权模式”设置。删除不再需要的令牌文件读写；迁移时不要自动删除已有 `server_tokens.json`，先确保回滚仍可使用旧版。
5. 管理网页改用面板现有登录网关：确认管理域名整站受网关保护后，才移除 CapsWriter 的管理员密码表单和登录接口。保留网页对危险操作的二次确认、CSRF/Origin 等适用保护以及内部控制通道认证。若管理端仍能从未经网关的地址访问，先按用户的入口安排限制该访问，再删除原登录；不要仅凭浏览器里看到了登录页就认定网关已生效。
6. 同步修改 `desktop/package.ps1`、客户端与部署文档、相关测试。产物必须实际包含改后的 Python 客户端和桌面 UI，不能只在源码中改字段。

### B. 再配置面板与部署

1. 在部署面板登记语音反代流水线，目标为 Windows 上的 ASR `6016`；按实际可达地址配置轻量代理。不要手改由面板生成的 Caddyfile。确认代理支持 WebSocket Upgrade 和长连接。
2. 为语音站点启用「网关 → 机器门」，覆盖语音 WebSocket 实际路径；若服务在根路径，按面板规则使用整站模式 `/*`，并以实际请求验证匹配。给用户**现有的那把**面板 Key 增加该站权限，保持原 Key 不变。
3. 为网页管理站点配置现有的人用认证网关，转发到 Windows 管理端 `6017`。先验证未登录用户无法访问页面和管理 API，再上线去掉 CapsWriter 自身密码的版本。
4. 切换一台客户端做试运行，确认无问题后再更新其他客户端。服务器上只运行一个 ASR 模型实例；不要为配置网关而重复启动模型。

## 4. 必须通过的验收

- 不带 `X-API-Key` 和带错误 Key 连接语音域名：在网关被拒绝，ASR 不收到录音连接；带现有 Key：WebSocket 成功升级并完成一次真实识别。
- 远程便携客户端的长按录音、按键开关录音、边说边写、录完再写均能正常工作；局域网旧地址仍按用户选择可用。断线重连后不会重复输入或清空已输入文字。
- 客户端只有一个 Key 输入项；网页管理没有 CapsWriter 自建的令牌管理；服务端不再依赖 `server_tokens.json` 判定语音连接。
- 网页管理未通过现有网关登录时不可读状态、日志或执行启动/停止/重启；已登录用户可操作，且不会产生第二个 ASR 实例。
- 日志、便携包和仓库中搜不到真实面板 Key。测试仅用占位值记录命令和结果，不把 Key 写进测试报告。
- 将网络访问、HTTP 状态、实际录音结果、便携包路径与哈希、提交号写入交付记录；不要只凭单元测试宣称远程已可用。

## 5. 回退与交付

先保留旧版源码提交、便携包及服务器配置快照。若网关握手或真实录音失败，优先将客户端切回既有 LAN 地址，并恢复旧服务端版本；不要在问题未查明时改动防火墙或重启整台 Windows 主机。面板流水线和 Key 的站点授权可独立撤回。回退演练要确认旧版仍能读取原有 `server_tokens.json`。

交付时提交：改造提交号、更新后的部署说明、测试结果、便携包绝对路径与 SHA-256、面板流水线/域名（不含 Key）、尚未验证的项目。**不要在文档、提交或聊天中贴真实 Key。**

> 使用现有部署面板 Key 意味着客户端持有这把 Key 原本具备的面板权限。这是用户明确选择“一把 Key”的结果；开发者不要擅自另发 CapsWriter Key。若用户以后要缩小权限，应在部署面板调整同一把 Key 的作用域与站点授权。
